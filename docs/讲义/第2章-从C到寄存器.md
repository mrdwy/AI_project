## 2.1 内存映射：硬件对 C 来说就是地址

- **时长**：16 分钟
- **画面形式**：板书 + 动画 A2 + 录屏
- **本讲目标**：理解「外设寄存器 = 特殊内存地址」；能解释 volatile 为什么必须有；能说出 Flash/RAM/外设区在地址空间的大致位置。

### 前置

第 1 章完成；会用 Keil 单步调试和 Watch 窗口。

### 知识点

**1. 从指针说起**

- C 语言里 `int *p = (int*)0x40010800;` 就能拿到一个地址。对 CPU 而言，内存、外设、Flash 都在同一个地址空间里。
- **内存映射 I/O（MMIO）**：外设的控制寄存器被映射到一段固定地址。读这个地址 = 读外设状态；写这个地址 = 配置/控制外设。
- 例：STM32F103 的 GPIOA 基地址 `0x4001_0800`。`GPIOA->ODR` 就是基地址 + 偏移。

**2. 地址空间三块（动画 A2）**

```
0x0800_0000 ──┬── Flash（你的程序）
              │
0x2000_0000 ──┼── SRAM（全局变量、栈）
              │
0x4000_0000 ──┴── 外设寄存器区（APB1/APB2/AHB）
```

- Flash：掉电不丢，存代码和常量。
- SRAM：掉电丢，存变量。
- 外设区：读写它就在操作硬件。

**3. volatile 关键字（本课第一个必须吃透的概念）**

- 编译器优化会「自作聪明」：认为某个变量在循环里没被改，就把它缓存到寄存器，不再去内存读。
- 但硬件寄存器的值随时会被外设改变（如状态位、输入电平）。
- `volatile` 告诉编译器：**每一次读写都要真的去内存（地址）发生**，不许优化掉。
- 反例：
  ```c
  while ((GPIOA->IDR & 0x01) == 0) {}   // 没 volatile，可能被优化成死循环
  ```
- 关键话术：「volatile 不是给『人』看的，是给『编译器』下命令：别耍花招，老老实实去读地址。」

**4. 用调试器亲眼看到**

- 在 Keil 里把 `0x40010800` 附近地址加进 Memory 窗口，改一个变量，看地址上的值怎么变。
- 这一步建立「地址=硬件」的直觉。

### 演示步骤

1. **板书（3 分钟）**：画地址空间三块，标出 GPIOA 基地址。
2. **动画 A2（3 分钟）**：内存映射总览，Flash/SRAM/外设区如何被 CPU 通过总线访问。
3. **录屏（5 分钟）**：写一段代码，用指针直接读写 `0x40010800`，Watch 看变量；再打开 Memory 窗口看地址内容。
4. **录屏（4 分钟）**：演示 volatile 的差异——有无 volatile 时编译出的汇编（Keil 里看 Disassembly 窗口），说明优化差别。

### 口播要点

- 「对 CPU 来说，点灯和写数组没有区别——都是往某个地址写数。区别在于那个地址连着的是灯。」
- 「volatile 是你和编译器的合同：这地址上的值会自己变，你别缓存。」
- 「第 2 章开始，你写的每一行寄存器操作，都要能说出它在地址空间的哪个位置。」

### 踩坑提醒

- 忘记 volatile，输入检测的 while 循环被优化成死循环——现象是「读不到变化」。
- 把外设地址当普通内存随意 memcpy——外设寄存器有访问宽度和顺序要求。
- 基地址背错——不要背，去 RM 的寄存器映射表查。

### 课后动作

1. 打开 RM0008 的「存储器映射」章节，抄下 Flash / SRAM / APB2 起始地址。
2. 写一段带 volatile 和不带 volatile 的输入检测代码，对比 Disassembly。
3. 在 Keil Memory 窗口观察 GPIOA 基地址附近的 16 个字节。

### 动画脚本要求（A2）

- 画面：三块地址空间竖排（Flash / SRAM / 外设），CPU 在左，总线在中。
- 动作：CPU 发出一次读操作，总线点亮对应区块，返回数据。
- 旁白：「CPU 只认地址。地址指向 Flash 就读到指令，指向外设就动了硬件。」
- 时长：约 45 秒。

## 2.2 寄存器与位操作

- **时长**：18 分钟
- **画面形式**：动画 A3、A4 + 板书 + 录屏
- **本讲目标**：能用位操作改寄存器的某几位而不影响其他位；能解释读-改-写在中断场景下的风险。

### 前置

2.1 已看完；会用 `&` `|` `^` `~`。

### 知识点

**1. 寄存器 = 特殊地址上的 32 位变量**

- 一个外设有很多寄存器，每个有名字（如 `GPIOA_CRL`）和偏移。
- 一个 32 位寄存器里往往塞了多个「功能位」（位域）：比如 `CRL` 的每 4 位配置一个引脚的模式。

**2. 位域读法（RM 位定义表）**

- 读 RM 时，每个寄存器都有这样的表：

  | 位 | 名称 | 含义 |
  |----|------|------|
  | 31:24 | 保留 | 保持 0 |
  | 23:16 | MODE | 模式 |
  | 15:0 | ... | ... |

- 抄表要抄三样：**位范围、位名、取值含义**。这就是第 3 章喂给 AI 的素材。

**3. 位操作四件套（动画 A3）**

| 意图 | 代码 | 说明 |
|------|------|------|
| 置 1（某几位） | `reg \|= (1<<3);` | 或运算，不影响其他位 |
| 清 0（某几位） | `reg &= ~(1<<3);` | 先取反再与 |
| 翻转 | `reg ^= (1<<3);` | 异或 |
| 取某几位的值 | `(reg >> 3) & 0x01` | 右移后掩码 |

- 掩码思想：先用 `~mask` 把目标位清零，再或上新值——这是「改特定位」的标准写法。
- 多位域写法：
  ```c
  // 把 [7:4] 写成 0xA，不影响其他位
  reg = (reg & ~(0xF << 4)) | (0xA << 4);
  ```

**4. 读-改-写陷阱（动画 A4）**

- `reg |= ...` 实际是三步：**读出寄存器 → 在 CPU 里改 → 写回**。
- 若这三步之间发生了中断，ISR 也改了同一个寄存器，返回后主程序写回的会把 ISR 的改动**覆盖掉**（丢失更新）。
- 对策：
  - 关中断再改（`__disable_irq()` / `__enable_irq()`）；
  - 或使用硬件提供的「原子位操作」寄存器（有的外设有 BSRR 这类只写位寄存器，见 2.3）；
  - 或让 ISR 与主程序改不同寄存器。

- 关键话术：「`|=` 不是原子操作。中断一来，你的改位可能就被『回滚』了。」

### 演示步骤

1. **动画 A3（4 分钟）**：32 位寄存器可视化——格子图，演示 `|=` `&= ~` `^=` 逐位变化。
2. **录屏（5 分钟）**：写一段纯位操作代码，用 Watch/寄存器窗口看变化；故意写错掩码（如忘了取反），看结果。
3. **动画 A4（3 分钟）**：读-改-写竞争——主程序读出 0x0001，ISR 改成 0x0003，主程序写回 0x0005（丢了 ISR 的改动）。
4. **录屏（5 分钟）**：用一个实际寄存器复现（或示意性全局变量模拟），演示加关中断保护后正确。

### 口播要点

- 「位操作的口诀：置位用或，清位用与非，翻转用异或。」
- 「掩码先想清楚『哪些位要留、哪些位要动』，再写代码。」
- 「`|=` 读出来改完再写回去——三步，中断插一脚，你就丢数据。」
- 「BSRR 这类只写位寄存器，是硬件送你的『原子操作』礼物，能用就用。」

### 踩坑提醒

- `reg &= (1<<3)` 想清位——写错了，这会把其他位全清掉！正确是 `&= ~(1<<3)`。
- 多位域没先清零再赋值——旧值残留，新值或上去了变成乱码。
- 以为 `|=` 是原子的，在 ISR 与主程序共改一个寄存器时丢失更新。

### 课后动作

1. 写一个 `set_bits / clear_bits / toggle_bits` 三个内联函数，并用单元测试思路验证（可先在 PC 上用普通 int 模拟）。
2. 从 RM 抄一个寄存器的完整位定义表到 `docs/`。
3. 思考题：为什么 GPIO 的 ODR 常配一个 BSRR 寄存器来「只置位/只清位」？（下一讲揭晓）

### 动画脚本要求（A3 / A4）

- **A3**：32 个格子（bit31→bit0），颜色区分 0/1。三个动作——`|=` 某位变 1、`&= ~` 某位变 0、`^=` 某位翻转，其他位闪烁「不受影响」。旁白：「或运算置 1，与非清 0，异或翻转。」约 60 秒。
- **A4**：时间轴上下两条（主程序 / ISR）。主程序读寄存器→ISR 打断改值→主程序写回（旧值）→寄存器显示「ISR 的改动丢失」。红色高亮丢失。约 45 秒。

## 2.3 GPIO 点灯：第一个纯寄存器程序

- **时长**：18 分钟
- **画面形式**：动画 A5 + 板书 + 录屏 + 实拍（板上灯）
- **本讲目标**：不用库函数，纯寄存器点亮一个 LED；能说出「时钟→配置→输出」三步；理解库函数到底帮你做了什么。

### 前置

2.1–2.2 已看完；LED 接好（板载灯或外接，串 220Ω~1kΩ 电阻）。

### 知识点

**1. GPIO 输出三步（动画 A5）**

```
① 开时钟      RCC->APB2ENR |= (1 << 2);   // GPIOA 时钟
② 配置模式    GPIOA->CRL &= ~(...);       // 清位
              GPIOA->CRL |=  (...);       // 设为推挽输出 2MHz
③ 输出电平    GPIOA->ODR |=  (1 << 0);   // PA0 = 1，灯亮
              GPIOA->BSRR = (1 << 16);   // PA0 = 0（只清位，原子）
```

- **为什么 BSRR 更好**：`BSRR` 低 16 位「置 1」、高 16 位「清 0」，是只写寄存器，天然避免读-改-写竞争。
- 关键话术：「三步走：先给外设通电（时钟），再告诉它怎么工作（配置），最后才让它干活（数据）。」

**2. 与库函数对照**

| 纯寄存器 | 库函数（StdPeriph/HAL） | 库帮你做了什么 |
|----------|-------------------------|----------------|
| 手动写 RCC->APB2ENR | `RCC_APB2PeriphClockCmd(...)` | 名字可读、可移植 |
| 手动写 CRL/CRH | `GPIO_Init(...)` | 帮你算位、防写错 |
| 手动写 ODR/BSRR | `GPIO_SetBits/ResetBits` | 帮你封装原子操作 |

- 本课要**先会寄存器，再用库**——不然库是魔法。
- 关键话术：「库不是敌人，是翻译。你先听得懂原文，再用翻译不迟。」

**3. 引脚模式速查（CRL/CRH 每 4 位配一个引脚）**

| 配置 | 含义 |
|------|------|
| 0x0 | 模拟输入 |
| 0x4 | 浮空输入 |
| 0x8 | 上下拉输入 |
| 0x3 | 推挽输出 50MHz（常用） |
| 0x5 | 复用推挽输出 50MHz（串口/PWM 用） |
| 0x7 | 复用开漏（I2C 用） |

**4. 场景迁移（智能车）**

- 点灯的同一套操作，换成「电机使能脚」「方向脚」「传感器电源控制」。
- 例：`PB12 = 1` 让 TB6612 驱动板的 STBY 口拉高，电机才能动。

### 演示步骤

1. **动画 A5（3 分钟）**：GPIO 输出框图——时钟门 → 模式寄存器 → 输出数据寄存器 → 引脚 → LED。
2. **录屏（6 分钟）**：从空 main 开始，纯寄存器点灯：先写错（不开时钟），看灯不亮；加上时钟，成功。
3. **实拍（2 分钟）**：板上灯亮灭；换成控制一个外接 LED 或电机驱动使能脚。
4. **录屏（5 分钟）**：用库函数实现同样的点灯，逐步展开库源码，一一对应寄存器操作。
5. **录屏（2 分钟）**：用 BSRR 做快速翻转（呼吸灯/闪灯），说明原子位操作的好处。

### 口播要点

- 「第一行永远是开时钟。不开时钟，你写寄存器等于对空气说话。」
- 「CRL/CRH 每 4 位管一个引脚，抄表要抄准。」
- 「库函数不是魔法，展开就是你刚写的那几行寄存器。」
- 「点灯只是开始，把 `LED` 换成 `MOTOR_EN`，你已经在控制智能车了。」

### 踩坑提醒

- 不开时钟就配置寄存器——灯不亮，新手最常见。
- CRL/CRH 混淆（PA0-7 用 CRL，PA8-15 用 CRH）。
- 用 ODR 读-改-写在 ISR 里改同一个端口——改用 BSRR。
- LED 接反 / 限流电阻没接——灯不亮或烧灯。

### 课后动作

1. 纯寄存器实现「LED 闪烁 1Hz」，再实现「按键翻转 LED」（输入读 IDR）。
2. 同一功能用库函数写一遍，做一份「寄存器 ↔ 库函数」对照笔记。
3. 场景题：把点灯代码改成控制 TB6612 的 STBY 引脚（只写思路，不动真车）。

### 动画脚本要求（A5）

- 画面：GPIO 输出框图——RCC 时钟门（开关）、CRL/CRH（配置盒）、ODR/BSRR（数据盒）、引脚、LED。
- 动作：① 时钟开关闭合（变绿）→ ② 配置盒高亮 → ③ 数据盒写 1 → LED 亮。
- 旁白：「三步：通电、配置、干活。顺序错了，灯不亮。」约 45 秒。

## 2.4 时钟树

- **时长**：16 分钟
- **画面形式**：动画 A6 + 板书 + 录屏
- **本讲目标**：能画出 STM32F103 的简化时钟树；能解释为什么「开时钟」是第一步；能说出 HSI/HSE/PLL 的关系与选择。

### 前置

2.3 已点灯成功。

### 知识点

**1. 为什么第一步是开时钟**

- MCU 内部每个外设都有一个「时钟门」。门关着，外设不工作，寄存器写不动（或写了也不生效）。
- 类比：工厂没通电，机床不转。

**2. 时钟源三种（动画 A6）**

| 源 | 全称 | 频率 | 特点 |
|----|------|------|------|
| HSI | 高速内部时钟 | 8MHz（RC） | 免外部晶振，精度一般，上电默认 |
| HSE | 高速外部时钟 | 8MHz（晶振） | 精度高，串口/USB 常用 |
| PLL | 锁相环 | 倍频后最高 72MHz | 从 HSI/HSE 倍频，跑高速必须用 |

**3. 简化时钟树（F103）**

```
HSE(8M) / HSI(8M)  →  PLL(×9)  →  SYSCLK(72M)  →  AHB(/1)  →  APB1(/2=36M) / APB2(/1=72M)
```

- SYSCLK：系统主频。
- AHB：总线（CPU、DMA、内存）。
- APB1（低速）：USART2/3、TIM2-7、I2C…最高 36MHz。
- APB2（高速）：USART1、GPIO、ADC、TIM1…最高 72MHz。
- **查外设属于哪条总线，决定去哪个时钟寄存器使能**（RCC_APB1ENR / RCC_APB2ENR）。

**4. 常见操作**

- 开外设时钟：`RCC->APB2ENR |= (1<<2); // GPIOA`
- 改主频：配置 `RCC->CFGR`（PLL 倍频、总线分频），并同步改 Flash 等待周期（`FLASH->ACR`）。
- 初学建议：**不要乱改主频**，用默认或库函数 SystemInit 的配置；改主频是踩坑大户。

**5. 智能车场景**

- PWM 用 TIM，TIM 时钟来自 APB。要算 PWM 频率，必须知道 TIM 输入时钟是多少——这就要看时钟树。

### 演示步骤

1. **板书（3 分钟）**：画简化时钟树，标出 APB1/APB2 各挂哪些外设。
2. **动画 A6（3 分钟）**：时钟信号从晶振出发，经 PLL 倍频，经分频器到各总线，各外设的时钟门逐一打开。
3. **录屏（5 分钟）**：查 RM 的 RCC 章节，确认 GPIOA 在 APB2；写使能代码，用寄存器窗口看 RCC_APB2ENR 的位变化。
4. **录屏（4 分钟）**：故意不开时钟，配置 GPIO 并写 ODR——灯不亮；开时钟后灯亮。
5. **录屏（1 分钟）**：演示 SystemInit（启动文件里调用）把时钟配到 72MHz 的存在。

### 口播要点

- 「时钟是外设的心跳。心跳停了，外设就是块硅。」
- 「APB1 慢速外设、APB2 快速外设——查表，别背。」
- 「改主频是高危操作，Flash 等待周期没跟上，芯片直接跑飞。初学先别动。」
- 「算 PWM 频率时，先问自己：TIM 的输入时钟到底是多少？答案在时钟树里。」

### 踩坑提醒

- 把 GPIO 使能写进 APB1ENR（实际在 APB2ENR）——位位置查 RM。
- 改主频后串口乱码——波特率是按主频算的，主频变了没重算。
- 以为「默认时钟就够了」——跑 72MHz 才能让某些性能达标，且 PLL 配置要注意合法性。

### 课后动作

1. 画一张自己的简化时钟树，标出 HSE/HSI/PLL/SYSCLK/APB1/APB2。
2. 查 RM，确认 USART1、USART2、TIM2、TIM3、I2C1 各挂在哪条总线。
3. 思考题：如果系统主频从 72MHz 改成 36MHz，串口波特率寄存器要怎么改？（下一章讲串口时验证）

### 动画脚本要求（A6）

- 画面：树形图——晶振（左）→ PLL（倍频盒）→ SYSCLK → AHB/APB1/APB2 分频盒 → 各外设（右排）。
- 动作：时钟信号像水流，经倍频变粗，经分频变细；每个外设前有一个「时钟门」开关。
- 旁白：「时钟从晶振来，倍频提速，分频给各总线。每个外设前有扇门，门不开，外设不动。」约 50 秒。

## 2.5 中断系统

- **时长**：20 分钟
- **画面形式**：动画 A7 + 板书 + 录屏 + 实拍（按键）
- **本讲目标**：能说出中断响应的完整链路（中断源→NVIC→向量表→ISR）；能配置一个 EXTI 外部中断；知道 ISR 里该做什么不该做什么。

### 前置

2.3–2.4 已完成；一个按键接在 GPIO 上（建议接 PA0，低电平有效，配上拉）。

### 知识点

**1. 为什么需要中断**

- 轮询（polling）：CPU 一直查按键——效率低、响应慢、主循环被卡。
- 中断（interrupt）：硬件事件主动「喊」CPU，CPU 暂停当前事去处理，处理完回来。
- 智能车场景：碰撞开关、编码器脉冲、超时——都靠中断。

**2. 中断响应链路（动画 A7）**

```
外设事件（如 EXTI0 上升沿）
    ↓ 触发
中断源（挂起位）
    ↓ 使能 + 优先级
NVIC（嵌套向量中断控制器）仲裁
    ↓ 查表
向量表（中断号 → ISR 入口地址）
    ↓ 跳转
ISR（中断服务函数）
    ↓ 清中断标志
返回主程序
```

**3. 三个必须做的事**

1. **使能外设中断**（如 `EXTI->IMR`）与**使能 NVIC 通道**（`NVIC_EnableIRQ`）。
2. **写 ISR**：函数名必须与启动文件里向量表的名字一致（如 `EXTI0_IRQHandler`）。
3. **清中断标志**：ISR 里第一件事/最后一件事把挂起位清掉，否则反复进中断（死循环）。

**4. ISR 里的「短平快」原则**

- 只做最少的事：置标志、收数据、翻转引脚。
- 不要：延时、printf（除非用 DMA/异步）、malloc、复杂运算、等待标志位。
- 关键话术：「ISR 是『消防队进屋只救人』，不是『进来装修』。」

**5. 优先级与嵌套**

- 数值越小优先级越高（Cortex-M 的设计）。
- 高优先级可打断低优先级（嵌套）。
- 相同优先级：不嵌套，按自然顺序。
- 同一 ISR 内可临时关中断（`__disable_irq()`）保护临界区。

### 演示步骤

1. **板书（3 分钟）**：画中断链路，标出「使能」「优先级」「向量表」「清标志」四个关键点。
2. **动画 A7（3 分钟）**：主程序执行→中断触发→保存现场→跳 ISR→清标志→恢复现场→返回。
3. **录屏（7 分钟）**：配置 EXTI0（PA0）上升沿中断，写 ISR 翻转 LED。烧录后按键点灯。
4. **录屏（4 分钟）**：故意不在 ISR 清标志——观察 LED 狂闪/卡死；加上清标志恢复正常。
5. **录屏（2 分钟）**：用逻辑分析仪（或动画示意）看 ISR 执行时间，说明「短平快」。
6. **实拍（1 分钟）**：按键点灯效果；场景迁移——按键换碰撞开关。

### 口播要点

- 「轮询是『一直问』，中断是『它喊我』。智能车里事件多，必须用中断。」
- 「链路四步：触发 → NVIC 仲裁 → 向量表找 ISR → 清标志返回。」
- 「不清中断标志 = 反复进出 ISR = 死机。这是新手中断的第一大坑。」
- 「ISR 里只做最少的事。复杂逻辑搬回主循环（用标志位通信）。」

### 踩坑提醒

- ISR 函数名写错（与启动文件向量表不一致）——根本进不去 ISR。
- 忘记 `NVIC_EnableIRQ` 或 `EXTI->IMR`——事件触发了但不响应。
- 不清挂起位——中断风暴。
- 在 ISR 里调 printf / 延时——主循环饿死、串口卡死。
- 按键抖动——需消抖（硬件 RC 或软件延时/状态机），否则一次按键多次中断。

### 课后动作

1. 实现「按键中断翻转 LED」，并故意复现一次「不清标志」的故障，写一篇观察笔记。
2. 把按键换到另一个引脚，走一遍「引脚→EXTI 线→向量号」的映射查表。
3. 思考题：编码器 A/B 相脉冲用什么中断配对？（提示：双边沿；进阶留到智能车实战）

### 动画脚本要求（A7）

- 画面：上下两行——上行主程序指令流（方块前进），下行 ISR。中间是 NVIC 与向量表。
- 动作：外设事件闪烁 → NVIC 高亮仲裁 → 向量表连线到 ISR → 主程序方块「暂停」并出现「保存现场」→ ISR 方块执行 → 清标志 → 恢复现场 → 主程序继续。
- 旁白：「事件来了，CPU 暂停手头事，跳去 ISR，清标志，回来接着干。」约 60 秒。

## 2.6 外设寄存器套路（以 UART 为例）

- **时长**：18 分钟
- **画面形式**：动画 A8 + 板书 + 录屏
- **本讲目标**：掌握「任何外设都通用的五步套路」；能纯寄存器配置 UART 并收发一个字节；能举一反三到 I2C/SPI/ADC。

### 前置

2.1–2.5 已完成；USB-TTL 已接好（第 1 章）。

### 知识点

**1. 外设五步套路（本课最重要的方法论之一）**

```
① 开时钟        RCC->APBxENR |= ...
② 配置引脚复用  GPIOx->CRL/CRH 设为 复用推挽/复用开漏/浮空输入
③ 配置外设参数  波特率、数据位、校验、停止位、模式
④ 使能外设      USARTx->CR1 |= UE ...
⑤ 收发数据 / 等状态位 / 开中断
```

- 关键话术：「外设千千万，套路就五步。换一个外设，只是第③步参数不同。」

**2. UART 基础（动画 A8）**

- 帧格式：起始位(1) + 数据位(8) + 校验位(0/1) + 停止位(1)。
- 波特率：每秒传输的位数。常用 115200 / 9600。
- 波特率计算（F103）：`USARTx->BRR = fPCLK / 波特率`（具体分频查 RM）。
- 引脚：TX（推挽复用输出）、RX（浮空输入）。

**3. 关键状态位（收发都要看）**

| 标志 | 含义 | 用途 |
|------|------|------|
| TXE | 发送数据寄存器空 | 可以写下一个字节 |
| TC | 发送完成 | 一帧发完 |
| RXNE | 接收寄存器非空 | 可以读一个字节 |

- 发送：等 TXE，写 DR。
- 接收：等 RXNE，读 DR。
- 关键话术：「状态位是外设的『红绿灯』。不看灯就冲，数据就丢。」

**4. 纯寄存器最小收发**

```c
// 使能后
USART1->DR = 'A';                    // 发
while (!(USART1->SR & (1<<7)));      // 等 TXE

while (!(USART1->SR & (1<<5)));      // 等 RXNE
char c = USART1->DR;                 // 收
```

**5. 举一反三表**

| 外设 | ③参数配置 | ⑤数据收发 | 状态位/中断 |
|------|-----------|-----------|-------------|
| UART | BRR、CR1/2/3 | DR | TXE/RXNE/TC |
| I2C | 时钟频率、自身地址 | DR + START/STOP | ADDR/SB/BTF |
| SPI | 波特率分频、CPOL/CPHA、位宽 | DR | RXNE/TXE/BSY |
| ADC | 采样时间、通道、触发 | DR | EOC |
| TIM | PSC、ARR、模式 | CCR | UIF/CCxIF |

### 演示步骤

1. **板书（3 分钟）**：写「五步套路」，标注每步查 RM 的哪一章。
2. **动画 A8（3 分钟）**：UART 帧时序——空闲高电平、起始位下降沿、8 数据位（LSB 先）、停止位。
3. **录屏（7 分钟）**：纯寄存器配置 USART1（PA9 TX / PA10 RX），发一个字符 'A'，串口助手看到；再收一个字符回显。
4. **录屏（3 分钟）**：故意把波特率改错，看串口乱码；改回来正常。
5. **录屏（2 分钟）**：打开 RM 的 I2C 章节，用「五步套路」指出它对应哪几节——演示举一反三。

### 口播要点

- 「五步套路背下来：时钟、引脚、参数、使能、收发。」
- 「TXE 是『能写了』，RXNE 是『能读了』。不等标志位，数据就丢。」
- 「波特率算错了，串口就是乱码制造机。」
- 「I2C/SPI/TIM 全是这个套路。下一次换外设，你只需要查第③步的参数。」

### 踩坑提醒

- 忘记 GPIO 复用配置——TX 发不出去。
- 波特率寄存器写错（fPCLK 用错总线频率）——乱码。
- 用阻塞式 `while(!TXE)` 在主循环里发长串——卡死主循环（第 3 章会教用中断/DMA 改善）。
- RX/TX 不交叉、不共地——第 1 章的坑会再来一次。

### 课后动作

1. 纯寄存器实现「串口发送 hello」与「收到字符回显」。
2. 做一份《外设五步套路对照表》，至少填 UART、GPIO 两行，I2C/SPI 留空待填。
3. 场景题：智能车要把「当前速度」发给上位机——列出用到的外设与套路步骤。

### 动画脚本要求（A8）

- 画面：UART 时序波形（空闲→起始→D0..D7→停止），下方标出 TXE/RXNE 标志。
- 动作：波形逐位出现，TXE 灯在「写 DR 后」熄灭、在「移位完成后」点亮；RXNE 在停止位后点亮。
- 旁白：「一帧 10 位。起始位是发令枪，停止位是撞线。看 TXE 写，看 RXNE 读。」约 50 秒。

## 2.7 TIM 与 PWM：电机调速

- **时长**：20 分钟
- **画面形式**：动画 A9 + 板书 + 录屏 + 实拍（电机）
- **本讲目标**：能纯寄存器产生一路 PWM；能算出 PWM 频率与占空比；能用 PWM 调直流电机转速（智能车核心能力）。

### 前置

2.1–2.6 已完成；有 TB6612/L298N 驱动板 + 直流减速电机（没有也能先看，用 LED 观察 PWM）。

### 知识点

**1. TIM 三件套**

| 概念 | 寄存器 | 含义 |
|------|--------|------|
| 预分频 PSC | TIMx->PSC | 把 TIM 时钟分频，决定计数频率 |
| 自动重装载 ARR | TIMx->ARR | 计数到多少翻回去，决定周期 |
| 捕获/比较 CCR | TIMx->CCRn | 与计数器比较，决定占空比 |

- 计数频率：`fCNT = fTIM / (PSC+1)`
- PWM 频率：`fPWM = fCNT / (ARR+1)`
- 占空比：`duty = (CCR+1) / (ARR+1)`（PWM1 模式向上计数）

**2. PWM 模式（动画 A9）**

- PWM 模式 1：CNT < CCR 时输出有效电平，否则无效。
- 有效电平极性可配（`CCER` 的 CCxP）。
- 预装载（Preload）：改 CCR/ARR 时不会「撕裂」当前波形，更新事件（UEV）时才生效——**调速时务必使能预装载**，否则占空比突变产生毛刺。

**3. 引脚配置**

- TIM 通道对应的引脚要设成**复用推挽输出**（0x9 或 0xB 等，查 RM 的 GPIO 复用表）。
- 例：TIM3_CH1 = PA6。

**4. 电机调速原理（智能车核心）**

- 直流电机平均电压 ∝ 占空比 → 转速 ∝ 占空比。
- 频率选择：一般 1kHz~20kHz。低于 1kHz 会有啸叫；高于 20kHz 一般听不见，但对驱动管开关速度有要求。
- **方向**用另一个 GPIO（或驱动板的 IN1/IN2）；PWM 只管速度。
- TB6612 接线示意：VM(电机电源)、VCC(逻辑 3.3/5V)、GND、AO1/AO2(接电机)、PWMA(接 PWM)、AIN1/AIN2(方向)、STBY(使能)。

**5. 与 2.6 套路对照**

- ①开时钟（TIM 在 APB1）②引脚复用 ③参数（PSC/ARR/CCR、PWM 模式、极性、预装载）④使能 TIM 与通道 ⑤改 CCR 调速。
- 关键话术：「TIM 只是五步套路多了一个『计数/比较』环节，别怕。」

### 演示步骤

1. **板书（3 分钟）**：画计数器三角波与 CCR 比较线，标出占空比。
2. **动画 A9（3 分钟）**：PWM 波形随 CCR 变化而变宽变窄，下方电机转速条同步变化。
3. **录屏（7 分钟）**：纯寄存器配置 TIM3_CH1 输出 1kHz PWM，用 LED（串电阻）观察亮度随占空比变化；改 CCR 看亮度变。
4. **实拍（4 分钟）**：接 TB6612 + 电机，占空比 0%→30%→70%→100%，电机转速变化；万用表量平均电压。
5. **录屏（2 分钟）**：改 ARR 看频率变化（LED 闪烁变快/变慢，或逻辑分析仪量频率）。
6. **录屏（1 分钟）**：强调预装载——不使能预装载时改 CCR，可能出现一次毛刺。

### 口播要点

- 「PWM 是『快速开关』：开得久占空比大，电机转得快。」
- 「PSC 定快慢（计数频率），ARR 定周期，CCR 定占空比。三个寄存器分工明确。」
- 「调速改 CCR，别改 ARR——改 ARR 会连频率一起变。」
- 「PWM 频率选 1k~20k：太低电机叫，太高驱动管发热。」
- 「这就是智能车的核心能力。第 4 章会把它包成模块，配 PID 闭环。」

### 踩坑提醒

- 引脚没配复用推挽——PWM 出不来。
- PSC/ARR 算错——频率不是你以为的那个数（用逻辑分析仪或示波器量一下）。
- 电机电源与逻辑电源不共地——电机不转或单片机复位。
- 用 LED 直接接 PWM 引脚不串电阻——烧 IO 或烧灯。
- 不使能预装载就调 CCR——占空比毛刺，电机顿挫。

### 课后动作

1. 用 LED 观察 100Hz / 1kHz / 10kHz 三个频率的 PWM（肉眼 / 相机 / 逻辑分析仪）。
2. 用万用表（直流电压档）量不同占空比下的平均电压，验证 duty×Vcc。
3. 写一份《TIM PWM 配置清单》：PSC、ARR、CCR、极性、预装载、引脚复用——第 4 章做电机模块时直接用。
4. 场景题：智能车要「前进/后退/调速/刹车」四态，列出需要的引脚与寄存器（不用写完整代码）。

### 动画脚本要求（A9）

- 画面：上方 PWM 波形（固定周期），下方「电机转速条」。
- 动作：CCR 从 0% 增到 100%，波形变宽，转速条升高，电机图标转得更快；ARR 改变时周期变短/变长，转速条不变。
- 旁白：「CCR 管宽窄（转速），ARR 管周期（频率）。调速改 CCR。」约 45 秒。
