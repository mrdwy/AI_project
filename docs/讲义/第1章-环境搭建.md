# 第 1 章 · 环境搭建

> 对应总大纲 `docs/compose/spec/ai-embedded-teaching.md` 第 1 章。本章 5 讲，平台 STM32。
> 贯穿目标：学员能独立把「源码 → 编译 → 烧录 → 运行 → 串口回传」整条链路跑通，并知道每一步在干什么。

## 1.1 开发板与工具链全景

- **时长**：15 分钟
- **画面形式**：实拍（硬件）+ 动画 A1（工具链数据流）+ 录屏
- **本讲目标**：认得清手上每件硬件的角色；能画出「一行代码从写下到板上跑起来」的完整链路。

### 前置

第 0 章已看完；硬件（至少 STM32 板 + USB-TTL + 下载器）已到手。

### 知识点

**1. 硬件角色逐一认**

| 硬件 | 角色 | 常见误区 |
|------|------|----------|
| STM32F103C8T6 最小系统板 | 运行你代码的目标 MCU | 「最小系统板」= MCU + 晶振 + 复位 + 电源 + 排针，不含调试器 |
| ST-Link / DAP-Link | 把编译好的固件写进 MCU 的下载器 | 不是「充电线」；DAP-Link 有些版本自带串口，可以省一个 USB-TTL |
| USB-TTL（CH340/CP2102/PL2303） | MCU 的 UART ↔ 电脑 USB，用来打印日志 | 必须 **共地**（GND 连 GND），否则乱码或无输出 |
| 杜邦线 / 面包板 | 连线 | 电源线和信号线分开理，短路是最常见的初学事故 |
| 万用表 | 测供电、测电平 | 开工前先量一下板子供电是不是 3.3V |

**2. 工具链数据流（动画 A1）**

```
[C 源码 .c/.h]
    ↓  预处理 → 编译 → 汇编 → 链接
[可执行镜像 .hex / .elf]
    ↓  烧录器（SWD/JTAG）
[MCU Flash]
    ↓  复位后 CPU 从向量表取指执行
[代码运行，GPIO/UART/... 动作]
    ↓  UART 输出
[电脑串口助手看到日志]
```

- 关键话术：「烧录器是『快递员』，串口是『回话的电话』。一个把代码送进去，一个让板子把话说出来。」

**3. 两类「看不见」的东西**

- **编译器**：把 C 变成机器码。Keil 里是 ARMCC（或 GCC）。报错信息它给。
- **驱动**：电脑认识下载器和 USB-TTL 的前提。设备管理器里能看到 COM 口 / 调试设备，才算装好。

**4. SWD vs JTAG vs UART**

- SWD：2 根线（SWDIO/SWCLK）+ GND + 3.3V，STM32 最常用调试口。
- JTAG：线多，老一点的芯片/ARM9 用。
- UART：**不是下载口**（除非芯片带 ISP bootloader），它是日志/通信口。

### 演示步骤

1. **实拍（4 分钟）**：桌面俯拍，逐一拿起硬件，说出角色；用万用表量一次供电。
2. **动画 A1 播放（2 分钟）**：工具链数据流，边播边讲每个环节。
3. **实拍（3 分钟）**：接线一次——ST-Link 接 SWD 四线（含供电），USB-TTL 接 UART 三线（TX/RX 交叉 + GND）。
4. **录屏（3 分钟）**：打开设备管理器，演示「插上下载器 / 拔掉 / 再插」，指出 COM 口和调试设备的出现。

### 口播要点

- 「先认人再干活：这是目标（MCU）、这是快递员（下载器）、这是电话（串口）。」
- 「驱动没装好，后面所有报错都是白排查——第一步永远是设备管理器。」
- 「TX 交叉 RX，GND 要共地。这两句话值一次返工。」
- 「SWD 不是下载线那么简单，它还是你后面打断点调试的生命线。」

### 踩坑提醒

- 数据线是「充电线」（只有电源脚）——插上没反应。换一根数据线试试。
- 下载器接了但不认：先查驱动，再查接线，再查供电（不要用杜邦线供电给整板电机类负载）。
- TX/RX 不交叉：有 TX 无 RX 或反之，串口助手一片空白。

### 课后动作

1. 只接线不写代码：把下载器和 USB-TTL 都接好，拍一张接线照片，标注每根线的作用。
2. 设备管理器截图：下载器和 COM 口都识别到的状态。
3. 用万用表量一次开发板 3.3V 轨，记下读数。

## 1.2 Keil MDK 环境

- **时长**：18 分钟
- **画面形式**：录屏为主
- **本讲目标**：能新建一个 Keil 工程、编译通过、烧录进板、并用断点单步调试。

### 前置

1.1 已看完，硬件接线已通。

### 知识点

**1. 安装三件套**

- Keil MDK 主程序（uVision）
- License（学习用途的评估许可；企业用需正版授权）
- Device Family Pack（DFP）：STM32F1 系列的器件支持包——**没装 DFP，新建工程时找不到芯片**

**2. 新建工程的标准动作**

1. Project → New μVision Project，选保存路径（**路径不要有中文和空格**）。
2. 选芯片：STMicroelectronics → STM32F103C8。
3. 运行环境（Run-Time Environment）勾选 CMSIS → Core，Device → Startup（只勾必要的，勾多了编译慢）。
4. 新建 `main.c`，写最小 `main()`（空 while(1)）。
5. 编译（F7），看 Build Output 窗口。

**3. 烧录设置（Options for Target）**

- Debug 标签：选 ST-Link Debugger → Settings → 确认 SWD 检测到芯片 IDCODE。
- Flash Download 标签：勾选 Reset and Run（烧完自动跑）。
- Utilities 标签：确认 Use Target Driver for Flash Programming。

**4. 调试四件套**

| 工具 | 用途 | 何时用 |
|------|------|--------|
| 断点（F9） | 程序停在某一行 | 定位「跑没跑到」 |
| 单步（F10 语句 / F11 进入） | 一行一行走 | 看变量怎么变 |
| Watch 窗口 | 盯变量 | 变量是否被正确改写 |
| 寄存器窗口 | 直接看外设寄存器 | 验证「我写的寄存器操作是否生效」（第 2 章核心） |

**5. 常见报错速查**

| 报错 | 常因 | 处理 |
|------|------|------|
| `No Debug Unit Device found` | 驱动 / 接线 / 供电 | 查设备管理器→查 SWD 四线→查 3.3V |
| `Error: Flash Download failed` | 芯片被读保护 / 时钟配置错 / 线太长 | 全片擦除一次；缩短杜邦线 |
| `#include <xxx.h> not found` | DFP 没装或路径有中文 | 装 DFP；改工程路径 |
| `undefined symbol` | 少了 .c 文件 / 函数没实现 | 把源文件加进工程组 |

### 演示步骤

1. **录屏（5 分钟）**：从安装包开始，装 DFP，新建工程，选芯片，勾 RTE。
2. **录屏（3 分钟）**：写空 main，编译，看 0 Error 0 Warning 的输出（有 Warning 也说明怎么看）。
3. **录屏（4 分钟）**：配置 Debug/Flash Download，烧录，板上现象（哪怕只是死循环）。
4. **录屏（5 分钟）**：进 Debug 模式，下断点、单步、Watch 一个变量、打开寄存器窗口看 GPIOA 的 CRL/CRH。

### 口播要点

- 「路径里有中文和空格，Keil 会在你最意想不到的时候崩给你看。」
- 「DFP 没装，不是 Keil 坏了，是它不认识你的芯片。」
- 「编译是『翻译』，烧录是『送货』，调试是『人肉跟踪』。三件事别混。」
- 「寄存器窗口是这门课的神器：从今天起，你写的每个寄存器操作，都要在这里亲眼看到它变了。」

### 踩坑提醒

- 勾太多 RTE 组件导致编译慢、符号冲突——初学只勾 CMSIS Core + Startup。
- 烧录成功但程序不跑：勾 Reset and Run；或按一下板上复位键。
- 调试模式下「程序停在奇怪的地方」：可能停在启动文件的死循环（如 HardFault），看 Call Stack。

### 课后动作

1. 建一个「空工程模板」目录，把它保存好——后面每一讲都在它基础上改。
2. 演示一次：在 main 里写 `volatile int i = 0; while(1){ i++; }`，断点 + Watch 看 i 变化。
3. 故意拔掉下载器的一根线，看报错长什么样，再接回去。

## 1.3 VSCode + GitHub Copilot

- **时长**：18 分钟
- **画面形式**：录屏
- **本讲目标**：VSCode 能打开并编辑 Keil 工程目录；Copilot 能在编辑器里补全、在 Chat 里对话，并且能读到你的工程上下文。

### 前置

1.2 已完成（Keil 工程已建好）。

### 知识点

**1. 分工先讲清**

| 工具 | 管什么 | 不管什么 |
|------|--------|----------|
| Keil MDK | 编译、烧录、断点调试、寄存器窗口 | 代码编辑体验、AI 对话 |
| VSCode | 编辑、搜索、Git、AI 对话（Copilot） | 不直接烧录（可用 Cortex-Debug 辅助调试，但本课以 Keil 调试为主） |

- 关键话术：「Keil 是车间，VSCode 是书房。你在书房写和问，在车间编和测。」

**2. VSCode 插件清单**

- C/C++（Microsoft）：语法、跳转、补全
- C/C++ Extension Pack（可选）
- Cortex-Debug（可选，配合调试器用；本课非必需）
- GitLens（可选，第 4 章 Git 用）
- 中文语言包（按需）

**3. Copilot 三种形态**

| 形态 | 特点 | 何时用 |
|------|------|--------|
| 补全（Inline） | 写代码时灰色提示，Tab 采纳 | 写样板代码、重复模式 |
| Chat | 对话框问答 | 解释概念、看代码、问报错 |
| Agent / Edit | 给任务让它改文件 | 第 3 章起的主战场 |

- 开通：GitHub 账号 → Copilot 订阅（学生有免费额度）→ VSCode 里装 GitHub Copilot + GitHub Copilot Chat 扩展 → 登录。
- 提醒：Copilot 会把你的代码片段发到云端（有企业版可关）。公司代码请遵守公司规定。

**4. 让 Copilot 读到你的工程**

- 用 VSCode 打开**工程根目录**（File → Open Folder），不要只打开单个 .c 文件——否则它没有项目上下文。
- 工作区里放一份 `README.md` 或 `AGENTS.md`/`.github/copilot-instructions.md`，写清楚：MCU 型号、工具链、编码规范、目录说明。这一步在第 3 章「上下文工程」会系统展开，今天先埋个种子。
- 对话里显式引用文件：`@workspace`、`#file:main.c` 等。

**5. 与 Keil 的协作流**

```
VSCode 里写代码 / 问 Copilot
    ↓ 切到 Keil（同一个目录）
Keil 编译 / 烧录 / 调试
    ↓ 把报错贴回 Copilot
Copilot 给修改建议 → 回 VSCode 改
```

### 演示步骤

1. **录屏（3 分钟）**：装 VSCode 与两个扩展，打开 Keil 工程目录，展示左侧文件树。
2. **录屏（4 分钟）**：装 Copilot 扩展、登录、开通订阅；演示 inline 补全（写 `int add(` 让它补完）。
3. **录屏（5 分钟）**：Chat 里问「volatile 是什么」；再 `#file:main.c` 让它解释这段代码。
4. **录屏（4 分钟）**：写一个 `AGENTS.md`（或 copilot-instructions.md）模板：MCU=STM32F103C8T6、工具链=Keil MDK ARMCC、编码=C99、目录说明。演示加了之后再问，回答更贴工程。
5. **录屏（2 分钟）**：走一遍「VSCode 改 → Keil 编译」的来回。

### 口播要点

- 「不要用 VSCode 取代 Keil 烧录调试，至少本课前两章不用。先各司其职。」
- 「Copilot 看不见你的工程，多半是因为你只开了单个文件。打开文件夹。」
- 「给 AI 一份工程说明书（AGENTS.md），比你在对话里每次重述一遍，划算得多。」
- 「学生免费额度别浪费，先确认账号状态再开写。」

### 踩坑提醒

- 扩展装了但不补全：检查右下角 Copilot 图标是否已登录、是否被禁用（企业策略）。
- 打开单文件导致 AI 没上下文：Open Folder 打开根目录。
- AGENTS.md 里写中文注释后编码乱了：统一 UTF-8（第 1.5 讲细讲）。

### 课后动作

1. 把 1.2 建的空工程用 VSCode 打开，写好 AGENTS.md。
2. 让 Copilot Chat 解释一次你的 main.c，并对照 Keil 的编译结果验证它说的对不对。
3. 记录下：哪一次 Copilot 的回答是「看起来对但其实不对」的？留到第 3.2 讲当案例。

## 1.4 烧录器与串口

- **时长**：16 分钟
- **画面形式**：实拍 + 录屏
- **本讲目标**：烧录失败能按流程排查；串口日志能稳定抓到并保存；形成「日志留档」的习惯。

### 前置

1.1–1.3 已完成。

### 知识点

**1. 三种下载器对照**

| 下载器 | 线数 | 速度 | 备注 |
|--------|------|------|------|
| ST-Link V2 | 4（SWDIO/SWCLK/GND/3.3V） | 中 | 便宜、常见；山寨版质量参差 |
| DAP-Link | 4 + 可能带 USB 串口 | 中 | 一个设备搞定下载+串口，推荐初学 |
| J-Link | 4 | 快 | 贵，功能强；有 EDU/EDU mini 版 |

**2. 烧录失败排查流程（按序，不跳步）**

```
1. 设备管理器认没认？ → 驱动问题
2. SWD 四线接对没？线是否过长（>20cm 要降速）？
3. 目标板供电够不够？（下载器供电带不动大负载）
4. 芯片是否被读保护 / 是否被别的工具占着？
5. Keil SWD 频率是否过高？（降回 100kHz 再试）
6. 全片擦除一次（Erase Full Chip）
```

- 关键话术：「排查烧录问题，永远是『先认设备、再认线、最后才怀疑芯片』。」

**3. 串口工具三选一**

| 工具 | 平台 | 特点 |
|------|------|------|
| XCOM / SSCOM | Windows | 国产、中文界面、好上手 |
| PuTTY | 跨平台 | 轻量，可保存日志 |
| VSCode Serial Monitor / Arduino 串口监视器 | 跨平台 | 和编辑器同屏 |

**4. 串口参数与日志习惯**

- 参数：波特率（常见 115200 / 9600）、8N1（8 数据位、无校验、1 停止位）。
- **TX/RX 交叉**：开发板 TX → USB-TTL RX，开发板 RX → USB-TTL TX。
- **共地**：GND 必须连。
- 日志留档：每次实验保存一份带时间戳的日志文件。第 5 章调试时你会感谢自己。
- 建议在代码里加一个简单日志宏，带模块名和等级（第 4 章会规范化，今天先用 `printf` 或轮询发送）。

**5. 常见现象对照**

| 现象 | 可能原因 |
|------|----------|
| 串口助手全无输出 | TX/RX 不交叉、波特率错、代码没跑、没共地 |
| 乱码 | 波特率不匹配、晶振频率与代码配置不一致 |
| 输出断断续续 | 接触不良、USB 供电不足、代码在死循环里阻塞发送 |
| 插上后设备管理器没有 COM | 驱动未装（CH340/CP2102 要装对应驱动） |

### 演示步骤

1. **实拍（3 分钟）**：三种下载器实物对比，接线方式。
2. **录屏（5 分钟）**：故意制造一次烧录失败（比如拔掉 SWDIO），按排查流程走一遍，逐条验证。
3. **实拍（2 分钟）**：串口接线特写，强调 TX/RX 交叉与共地。
4. **录屏（5 分钟）**：XCOM 打开串口，看到输出；保存日志；改波特率演示乱码，再改回来。
5. **录屏（1 分钟）**：把日志文件按 `YYYYMMDD_主题.log` 归档。

### 口播要点

- 「烧录失败是常态，会排查比会烧录更值钱。」
- 「TX 交叉 RX，GND 要共地——说三遍，值一次返工。」
- 「日志不是调试的副产品，日志是调试的证据。从今天起，每次实验都留档。」
- 「乱码先查波特率，再查晶振配置，别一上来就怀疑芯片。」

### 踩坑提醒

- 用下载器给整板供电再挂电机/传感器，电压跌落导致复位——电源要分开考虑。
- 串口助手开了两个实例抢同一个 COM 口——后开的没输出。
- 日志只看屏幕不保存——第 5 章做回归对比时无据可查。

### 课后动作

1. 故意制造 3 种烧录失败（拔线、降速、全片擦除），各写一行排查记录。
2. 用串口工具抓 10 分钟日志并保存，文件名带日期。
3. 画一张自己的接线图（可用纸笔拍照），标注每根线。

## 1.5 资料检索与工程卫生

- **时长**：15 分钟
- **画面形式**：录屏 + 板书
- **本讲目标**：能独立找到并读懂 RM/DS/勘误；建立目录与编码规范，避开中文路径与 GBK/UTF-8 陷阱。

### 前置

1.1–1.4 已完成。

### 知识点

**1. 三份文档，各司其职**

| 文档 | 全称 | 回答什么问题 | 去哪找 |
|------|------|--------------|--------|
| DS | Datasheet | 这颗芯片的电气特性、封装、引脚定义、外设列表 | ST 官网 / 立创商城详情页 / 数据手册网站 |
| RM | Reference Manual | **每个寄存器每一位是什么意思**——本课最常翻 | ST 官网，STM32F103 的 RM0008 |
| 勘误表 | Errata Sheet | 已知的芯片/手册错误与 workaround | ST 官网 |

- 关键话术：「DS 告诉你『它是什么』，RM 告诉你『怎么用』。第 2 章开始天天翻 RM。」

**2. 怎么读 RM（第 2 章会反复用）**

- 先看目录：外设章节（GPIO/USART/TIM...）+ 寄存器映射章节。
- 读一个外设的固定套路：功能描述 → 框图 → 寄存器列表 → 位定义表。
- 学会用「位定义表」做笔记：把你要操作的位单独抄出来（这一步也是第 3 章喂给 AI 的「硬件真相」素材）。

**3. 目录与命名规范（从今天起执行）**

```
project/
├── docs/          # 手册摘录、笔记、接线图
├── ref/           # 官方例程、参考驱动（只读，不改）
├── src/           # 自己的源码
├── prompts/       # AI 提示词与对话存档（第 3 章用）
└── README.md      # 工程说明（也是给 Copilot 的说明书）
```

- 命名：文件夹用英文或拼音，避免空格；源文件用 `模块_功能.c`（如 `drv_uart.c`、`app_motor.c`）。

**4. 编码陷阱（Windows 上的重灾区）**

| 陷阱 | 后果 | 对策 |
|------|------|------|
| 中文路径 / 空格 | Keil 报错、脚本失败 | 工程目录用英文 |
| GBK vs UTF-8 混用 | 中文注释乱码、文件损坏 | **统一 UTF-8（无 BOM）** |
| VSCode 与 Keil 编码不一致 | 一边好一边乱 | VSCode 设置里把编码钉死 UTF-8 |
| PowerShell 默认编码 | 写文件把 UTF-8 搞坏 | 不用 PS 直接改源文件字节；用编辑器 |

- Windows 上 VSCode 设置示例（settings.json）：
  ```json
  {
    "files.encoding": "utf8",
    "files.eol": "\n"
  }
  ```

**5. 可选：逻辑分析仪 / 入门示波器**

- 逻辑分析仪：抓数字时序（UART/I2C/SPI），8 通道 24MHz 足够入门，几十块钱。
- 示波器：看模拟波形、PWM、毛刺、电源纹波。
- 何时需要：第 2.7 PWM 电机调速、第 5.3 硬件观测会正式用。今天只需知道「它们是干什么的」。

### 演示步骤

1. **录屏（4 分钟）**：打开 ST 官网，找到 STM32F103 的 DS、RM0008、勘误表，下载归档到 `docs/`。
2. **录屏（4 分钟）**：打开 RM0008 的 GPIO 章节，演示「功能描述→框图→寄存器列表→位定义表」的读法，并抄 3 个位到笔记。
3. **录屏（4 分钟）**：建目录规范模板（docs/ref/src/prompts + README.md），提交一份初始笔记。
4. **录屏（3 分钟）**：演示编码事故——故意用错误编码保存一个带中文注释的文件，看乱码；再钉成 UTF-8 修好。

### 口播要点

- 「DS 是名片，RM 是说明书。你想改寄存器，只有 RM 能告诉你每一位什么意思。」
- 「读 RM 别从头读到尾——按『外设→框图→寄存器→位表』四步走。」
- 「目录规范是给未来的自己和 AI 看的。今天省五分钟，第 3 章多花一小时。」
- 「中文路径和编码问题，是 Windows 嵌入式开发里最阴间的坑之一。统一 UTF-8，工程目录用英文。」

### 踩坑提醒

- 学员只收藏文档不读文档——让其现场抄 3 个位定义到笔记，走一遍流程。
