# 第 6 章 · 电赛 / 智能车收束与进阶

> 对应总大纲 `docs/compose/spec/ai-embedded-teaching.md` 第 6 章。本章 2 讲，平台双平台。
> 贯穿目标：把前 5 章的能力迁移到电赛/智能车实战——学会拆解赛题、组织项目、规划排期；并明确进阶路线，知道怎么继续走。

## 6.1 赛题拆解方法

- **时长**：18 分钟
- **画面形式**：录屏 + 拆解图 + 真题案例
- **本讲目标**：能从电赛真题读出硬件需求、模块划分、排期与取舍；掌握「原理入门支撑作品」的方法论（不追新外设，把套路用熟）。

### 前置

第 1–5 章完成，有智能车/综合项目经验。

### 知识点

**1. 电赛 / 智能车题目长什么样**

电赛控制类常见题型：
- 循迹小车（沿轨迹行走）
- 自动泊车 / 倒库
- 物料搬运 / 分拣
- 速度控制 / 位置控制（如小车定点、定速）
- 避障 / 路径规划

智能车竞赛（飞思卡尔/恩智浦杯等）：
- 光电循迹 / 摄像头循迹
- 电磁循迹
- 高速越野、节能、智能视觉等组别

- 关键话术：「题目万变，套路不变：感知 → 决策 → 执行。」

**2. 赛题拆解五步法**

```
① 读题：圈出「输入、输出、约束、评分点」
② 转硬件需求：每个输入/输出对应什么外设
③ 模块划分：driver / app / util 三层（4.1）
④ 排期与取舍：MVP（最小可用）→ 加分项
⑤ 写文档：requirements / testcases（4.3）
```

**3. 示例：拆解「智能车循迹 + 避障 + 定速」**

| 步骤 | 内容 |
|------|------|
| ① 读题 | 输入：灰度传感器、超声波；输出：两路电机 PWM；约束：赛道宽度、限时；评分：完赛时间、脱轨次数 |
| ② 硬件需求 | ADC×N（灰度）、GPIO 触发+Echo 计时（超声波）、TIM/LEDC PWM×2、UART 日志 |
| ③ 模块划分 | driver: adc_track、ultrasonic、pwm_motor；app: app_control（状态机）；util: pid、filter |
| ④ 排期 | MVP：循迹+调速；加分：避障、速度闭环；再加：最优路径 |
| ⑤ 文档 | R-001 循迹、R-002 定速、R-003 避障；T-001~005 |

**4. 模块 ↔ 知识点对照（本课价值兑现）**

| 赛题模块 | 用到的本课内容 | 讲次 |
|----------|----------------|------|
| 电机调速 | TIM/PWM、LEDC | 2.7、3.1 |
| 循迹传感器 | ADC、滤波 | 2.6（举一反三）、5.4 |
| 超声波测距 | 定时器输入捕获/脉冲计数 | 2.7、2.6 |
| 决策控制 | 状态机、PID | 3.5、4.1 |
| 调试 | 调试思维、仪器 | 5.1–5.4 |
| 工程组织 | 分层、Git、测试 | 4.1–4.5 |
| AI 协作 | 提示词、验证闭环 | 3.2–3.5 |

**5. 排期与取舍（电赛实战智慧）**

- **MVP 先行**：先让「小车能沿轨迹跑完」，再加优化。
- 取舍原则：
  - 比赛评分点优先（如完赛时间 > 美观）
  - 稳定性 > 极限性能（跑完 10 次比跑 1 次极限更重要）
  - 会做的做完再做不会的
- 关键话术：「赛场上，70 分稳定做完 > 90 分做一半。」

**6. 原理入门如何支撑作品（本课主线的最终回答）**

- 不追新外设，把「五步套路」用熟——任何新外设都是套路的实例。
- 会查手册 = 会用任何芯片；会验证闭环 = 用 AI 不翻车；会调试 = 出问题不慌；会工程化 = 多人协作不乱。
- 关键话术：「原理不是死记寄存器，是『拿到任何外设都能上手』的能力。」

### 演示步骤

1. **录屏（3 分钟）**：展示一道电赛真题（如循迹小车），圈出输入/输出/约束/评分点。
2. **录屏（5 分钟）**：按五步法现场拆解——硬件需求、模块划分、排期。
3. **录屏（4 分钟）**：建立「模块 ↔ 知识点」对照表，把真题映射到讲次。
4. **录屏（4 分钟）**：写该题的 `requirements.md` 与 `testcases.md` 骨架。
5. **录屏（2 分钟）**：讨论取舍——如果时间只有 4 小时，先做哪部分？

### 口播要点

- 「题目万变，套路不变：感知 → 决策 → 执行。」
- 「拆解五步：读题、转硬件、分模块、排期、写文档。」
- 「70 分稳定做完 > 90 分做一半。先跑完，再优化。」
- 「原理的价值不是死记寄存器，是拿到任何外设都能上手。」

### 踩坑提醒

- 一上来就写代码——先拆需求、划模块、定排期。
- 追求极限性能忽略稳定性——跑完比跑快重要。
- 取舍时舍不得砍功能——MVP 先行，加分项后置。
- 不写文档直接做——AI 只能猜，协作乱。

### 课后动作

1. 找一道电赛/智能车真题，按五步法完整拆解（输出拆解文档）。
2. 建立该题的「模块 ↔ 知识点」对照表。
3. 写该题的 `requirements.md` 与 `testcases.md` 骨架。
4. 制定 4 小时排期表（MVP 优先）。

## 6.2 复盘与进阶路线

- **时长**：15 分钟
- **画面形式**：录屏 + 知识图谱 + 路线图
- **本讲目标**：回顾全课知识图谱；明确进阶方向（RTOS、更复杂总线、控制系统）；形成可长期复用的 AI 协作习惯。

### 前置

全课主体内容已看完。

### 知识点

**1. 全课知识图谱回顾**

```
                    AI 嵌入式开发
                          │
     ┌──────────┬────────┼────────┬──────────┐
   硬件原理   工具链    AI 协作   工程化    调试
     │          │        │        │          │
  内存映射   Keil     提示词   分层      现象假设
  位操作    VSCode    上下文   Git       二分定位
  GPIO      idf.py    验证闭环  文档驱动   仪器观测
  时钟树    烧录串口   信任等级  测试闭环   踩坑库
  中断      手册检索   防幻觉   迭代节奏
  UART
  TIM/PWM
```

- 三大铁律贯穿始终：
  1. 先开时钟（硬件认知）
  2. 寄存器/地址/时序要可查证（防 AI 幻觉）
  3. 业务不摸寄存器（工程分层）

**2. 三层模型的最终状态**

| 层 | 学完后你的水平 |
|----|----------------|
| 知道（30%） | 会用 AI 快速学习任何新外设/新平台 |
| 验证（50%） | 会跑通验证闭环，AI 写的代码必验证 |
| 攻克（20%） | 会系统性调试，能用仪器观测硬件真相 |

**3. 进阶路线（按需选）**

| 方向 | 内容 | 前置 |
|------|------|------|
| RTOS | FreeRTOS / Zephyr：任务、信号量、队列 | 本课 + 中断/时序 |
| 复杂总线 | CAN、USB、Ethernet | 本课 + 通信协议 |
| 控制系统 | PID 整定、卡尔曼、状态估计 | 本课 + 数学 |
| Linux 驱动 | i.MX/树莓派，字符设备/设备树 | 本课 + C 指针 |
| 无线协议 | BLE、MQTT、LoRa | 本课 + 网络基础 |
| 硬件设计 | 原理图、PCB、电源 | 本课 + 电路基础 |

- 关键话术：「RTOS 是锦上添花，不是雪中送炭。先把裸机和中断吃透。」

**4. 可长期复用的 AI 协作习惯（资产沉淀）**

| 资产 | 位置 | 复用方式 |
|------|------|----------|
| 提示词库 | `prompts/` | 新项目直接复制模板 |
| 上下文目录规范 | README/AGENTS.md | 新项目套用四类目录 |
| 手册摘录库 | `docs/` | 跨项目复用（同系列芯片） |
| 踩坑库 | `docs/pitfalls.md` | 同类问题直接查 |
| 测试钩子 | 串口测试指令 | 新固件照搬 |
| 三方对照表 | `docs/` | 新需求照填 |
| 金标准日志 | `test/golden/` | 回归对比 |

- 关键话术：「学完这门课，带走的不是智能车，是一套可复用的工作流。」

**5. 给自己的下一步（建议）**

1. 选一个进阶方向（如 RTOS 或 Linux 驱动），定 3 个月目标。
2. 用本课工作流做 2~3 个完整小项目（不必大，但要走全流程）。
3. 持续维护踩坑库与提示词库——这是你的护城河。
4. 输出：写博客/做视频/带新人——教是最好的学。

**6. 电赛/智能车的长期建议**

- 每年拿真题做一次「拆解练习」（6.1）。
- 积累自己的硬件模块库（电机、传感器、通信）。
- 团队协作：Git + 文档驱动 + 三方对照表是多人协作的最低配置。
- 关键话术：「比赛是一时的，工作流是一辈子的。」

### 演示步骤

1. **录屏（3 分钟）**：展示知识图谱，逐块回顾。
2. **录屏（3 分钟）**：展示进阶路线图，标注每个方向的前置与价值。
3. **录屏（4 分钟）**：展示资产清单（prompts/pitfalls/docs/test），说明复用方式。
4. **录屏（3 分钟）**：给学员示范「定 3 个月目标」——以 RTOS 为例，列学习清单。
5. **录屏（2 分钟）**：结束语——工作流 > 单一项目。

### 口播要点

- 「三大铁律：先开时钟、可查证、业务不摸寄存器。」
- 「RTOS 是锦上添花，先把裸机和中断吃透。」
- 「学完带走的不是智能车，是一套可复用的工作流。」
- 「比赛是一时的，工作流是一辈子的。」

### 踩坑提醒

- 学完就扔，不沉淀资产——下个项目从头踩坑。
- 直接冲 RTOS，裸机不熟——地基不稳。
- 只学不做——至少 2~3 个完整小项目走全流程。

### 课后动作

1. 画出自己的知识图谱，标出薄弱块。
2. 选一个进阶方向，定 3 个月目标与学习清单。
3. 整理自己的资产库：prompts、pitfalls、docs 模板、测试钩子。
4. （建议）输出一次：写一篇项目复盘或做一个分享。
