# AI 嵌入式开发视频教程 · 总大纲

## Report

## [S1] Problem

面向「会写 C 语言、但没独立做过完整嵌入式项目」的初学者，缺少一套同时覆盖三件事的成体系教程：

1. 传统嵌入式基本功（工具链、寄存器、外设、调试）；
2. AI 辅助写代码的正确姿势（上下文工程、提示词、验证闭环，而不是"让 AI 编地址"）；
3. 工程化能力（Git、文档驱动、测试闭环、系统性迭代）。

市面上的教程通常只教其中一到两件，且寄存器部分缺乏可视化讲解，AI 部分又停留在"贴代码"层面。本课程以**电赛 / 智能车**为应用载体、以**入门原理**为主线，把三件事缝起来；先出文档，再做视频。

## [S2] Design

### S2.1 课程定位

| 项 | 内容 |
|----|------|
| 目标学员 | 有 C 基础的嵌入式初学者（学生 / 转行 / 初级工程师） |
| 应用载体 | 电赛控制类真题 + 智能车（循迹 / 避障 / 电机调速） |
| 教学主线 | **入门原理为主**，智能车 / 电赛是每讲的引入场景与最终收束项目，不喧宾夺主 |
| 结课能力 | ①能看懂参考手册、用寄存器操作常见外设；②能用 AI 辅助完成一个完整小项目并验证其代码；③能用 Git + 文档驱动 + 测试闭环做可迭代开发；④能独立调试典型嵌入式故障 |
| 平台策略 | **中途切平台**：概念章（0–2）用 STM32 学原理；AI 与工程章（3–6）切 ESP32 落地 |
| 概念章平台 | STM32F103C8T6（或 F407）最小系统板 + Keil MDK |
| 工程章平台 | ESP32 + VSCode + ESP-IDF + GitHub Copilot |
| 烧录 / 串口 | ST-Link 或 DAP-Link（STM32）；ESP32 板载 USB；USB-TTL + XCOM / SSCOM / PuTTY |
| 规划课时 | 27–31 讲，每讲 12–20 分钟 |

**学习方法主线**（贯穿每讲）：AI 辅助三层模型 —— 30% 用 AI 加速"知道"，50% 靠实战"验证"，20% 攻克 AI 做不到的事（硬件观测、时序判断、真实故障）。

### S2.2 章节大纲

#### 第 0 章 导学（1 讲）

**0.1 这套课怎么学**
- 课程地图：原理入门为主线，智能车 / 电赛为应用载体
- 电赛 / 智能车要拿得出手的作品，底层缺的是什么（动机）
- AI 辅助学习三层模型的落地方式
- 硬件清单与购买建议（展开见附录 A）

#### 第 1 章 环境搭建（5 讲）—— STM32 起步

**1.1 开发板与工具链全景**
- STM32 最小系统板、USB-TTL、下载器、杜邦线
- 工具链数据流：源码 → 编译/链接 → 烧录 → 运行 → 串口回传
- 【动画 A1】工具链数据流图

**1.2 Keil MDK 环境**
- 安装、License、Device Family Pack
- 新建工程 / 编译 / 烧录 / 调试（断点、单步、Watch、寄存器窗口）
- 常见报错与排查路径

**1.3 VSCode + GitHub Copilot**
- VSCode + C/C++ 插件 + Cortex-Debug
- Copilot 安装与账号；补全模式 vs Chat 模式 vs Agent 模式
- 让 Copilot 读到你的工程（工作区、上下文、指令文件）
- 与 Keil 的分工：Keil 管编译调试，VSCode 管编辑与 AI 对话

**1.4 烧录器与串口**
- ST-Link / J-Link / DAP-Link 驱动、接线、供电
- 烧录失败排查（接线、BOOT 引脚、SWD 频率、供电不足）
- 串口工具：XCOM / SSCOM / PuTTY；抓日志与保存日志的习惯

**1.5 资料检索与工程卫生**
- 怎么找并读：参考手册（RM）、数据手册（DS）、勘误表、库函数源码
- 目录与命名规范、UTF-8 / GBK、中文路径陷阱
- 【可选】逻辑分析仪 / 入门示波器：何时需要、怎么用

#### 第 2 章 从 C 到寄存器（7 讲）—— STM32，概念通用

> 每讲引入场景取自智能车 / 电赛：点灯→电机使能、按键→碰撞开关、串口→调试链路、PWM→电机调速。

**2.1 内存映射：硬件对 C 来说就是地址**
- 指针、volatile、内存映射 I/O
- Flash / RAM / 外设寄存器区在地址空间的位置
- 【动画 A2】内存映射总览

**2.2 寄存器与位操作**
- 寄存器 = 特殊地址的 32 位变量；位域
- 置位 / 清位 / 翻转：`|=`、`&= ~`、`^=`、掩码
- 读-改-写陷阱（中断 / 并发下的丢失更新）
- 【动画 A3】32 位寄存器位翻转可视化
- 【动画 A4】读-改-写竞争问题

**2.3 GPIO 点灯：第一个纯寄存器程序**
- 时钟使能 → 端口配置 → 输出数据
- 与标准库 / HAL 点灯对照，看清库在帮你做什么
- 场景迁移：GPIO 输出驱动使能脚 / 方向脚
- 【动画 A5】GPIO 输出框图

**2.4 时钟树**
- 为什么第一步永远是开时钟
- HSI / HSE / PLL / 总线分频
- 【动画 A6】时钟树数据流

**2.5 中断系统**
- 中断源 → NVIC → 向量表 → ISR
- 优先级、嵌套、ISR 里的「短平快」原则
- EXTI 外部中断（按键 / 碰撞开关）
- 【动画 A7】中断响应全流程

**2.6 外设寄存器套路（以 UART 为例）**
- 一个外设的通用套路：时钟 → 引脚复用 → 参数配置 → 数据收发 → 状态 / 中断
- UART 帧格式、波特率计算
- 【动画 A8】UART 时序
- 举一反三：I2C / SPI / ADC 对照表（套路一致，细节查手册）

**2.7 TIM 与 PWM：电机调速**
- TIM 基本定时原理：计数器、预分频、重装载值
- PWM 输出：频率与占空比的计算、分辨率取舍
- 场景：用 PWM 调直流电机转速（智能车核心能力）
- 与 2.6 的通用套路对照：TIM 只是多了一个「计数/比较」环节
- 【动画 A9】PWM 占空比与电机转速

#### 第 3 章 用 AI 写嵌入式代码（5 讲）—— 切到 ESP32

**3.1 换平台不换概念：从 STM32 到 ESP32**
- ESP32 生态：ESP-IDF vs Arduino vs STM32 的习惯差异
- 工具链搭建：VSCode + ESP-IDF 插件 + Copilot（不再依赖 Keil）
- 概念迁移对照：时钟 / GPIO / 中断 / PWM 在 ESP32 上怎么对应
- 【表】STM32 ↔ ESP32 概念对照表

**3.2 AI 协作的正确姿势**
- AI 能做什么、不能做什么；最大的坑——寄存器地址 / 位定义幻觉
- 核心原则：AI 生成的每一段寄存器操作都要能对照手册验证
- 三层模型在写代码场景的落地

**3.3 上下文工程：让 AI 读到你的硬件**
- 目录规范（把「源码放同一路径」升级为上下文目录规范）：
  - `docs/` —— 手册摘录、寄存器表、时序要求（喂给 AI 的「硬件真相」）
  - `ref/` —— 官方例程、参考驱动、库函数源码
  - `src/` —— 自己的目标代码
  - `prompts/` —— 提示词模板与历史对话
- 怎么从手册里摘出「只需要的寄存器 / API」给 AI
- 【图】上下文目录结构图

**3.4 提示词模板**
- 需求描述模板：硬件约束 + 时序要求 + 寄存器 / 外设 + 验收标准 + 代码风格
- 反例 vs 正例对比（「帮我写个串口」 vs 完整提示词）
- 让 AI 解释它写的每一段寄存器操作，再对照手册
- 提示词库见附录 B

**3.5 验证闭环 + 综合实战**
- AI 生成 → 编译 → 烧录 → 串口观测 → 失败日志回喂 → 修正
- 常见翻车案例集：编造寄存器地址、忘了开时钟、中断号错、阻塞式死循环
- 用 Git 记录每个 AI 版本，便于回滚对比
- 综合实战：用 AI 写一个驱动（循迹传感器读取 / 电机 PID 骨架，二选一）

#### 第 4 章 工程框架与迭代（5 讲）—— ESP32

**4.1 从「能跑」到「工程」**
- 单文件 main.c 的问题
- 分层：`driver/`（硬件） / `app/`（业务） / `util/`（工具）
- 头文件组织、编译单元、防止重复包含

**4.2 Git 工作流**
- 安装、配置、仓库初始化、.gitignore
- 分支模型（main / develop / feature）
- Commit 规范：说清「为什么」而不是「改了什么」
- `git blame` / `git diff` / `git bisect` 调试
- AI 时代：怎么让 AI 生成规范的 commit message

**4.3 文档驱动开发**
- 需求文档 → 设计文档 → 测试用例 → 代码
- 「文本文档循环测试」落地：需求-测试-代码三方对照表
- 每次迭代先改文档再改代码；文档是 AI 的上下文源

**4.4 测试闭环**
- 分层测试：单元测试（PC 上跑纯逻辑，抽离硬件依赖） / 板级自测（串口指令 + 脚本） / 回归测试与金标准对比
- 【动画 A10】闭环测试流程图（需求 → 代码 → 测试 → 反馈 → 迭代）
- 怎么写一份「文本文档测试用例」并让它可执行

**4.5 迭代节奏 + 主线项目收束（智能车核心功能）**
- 小步提交、每步可回滚；版本号、变更日志、发布流程
- 反面教材：「东一榔头西一棒」 vs 系统性迭代
- CI 雏形：无硬件也能跑 lint + 编译 + 静态检查
- 收束：用 1–4 章方法在 ESP32 上实现智能车核心（循迹 + 避障 + 电机调速）
- 复盘：哪些环节省了时间、哪些 AI 帮倒忙

#### 第 5 章 调试实战（4 讲）

**5.1 调试思维：现象 → 假设 → 验证**
- 二分定位、最小复现、控制变量
- 日志分级与断言；什么时候该加日志、什么时候该下断点
- 【动画 A11】调试思维闭环

**5.2 工具调试深挖**
- 断点条件、数据断点 / Watchpoint、寄存器窗口、反汇编窗口
- `printf` / ITM / RTT 日志通道
- HardFault / 异常定位与调用栈回溯

**5.3 硬件观测**
- 万用表：供电、使能脚、静态电平
- 逻辑分析仪：UART / I2C / SPI 时序抓取与解码
- 示波器入门：PWM 波形、毛刺、干扰
- 【动画 A12】逻辑分析仪抓时序示意

**5.4 经典踩坑复盘（智能车 / 电赛向）**
- 电机不转 / 转速不对：驱动、PWM、供电、共地
- 传感器抖动 / 误触发：消抖、滤波、上拉、干扰
- 程序跑飞 / 死机：看门狗、栈溢出、中断优先级
- 电池电压跌落导致复位：电源设计与测量

#### 第 6 章 电赛 / 智能车收束与进阶（2 讲）

**6.1 赛题拆解方法**
- 从电赛真题读出硬件需求 → 模块划分 → 排期与取舍
- 真题对照表：哪道题用到本课哪些知识点（附录 D）
- 「原理入门」如何支撑作品：不追新外设，把套路用熟

**6.2 复盘与进阶路线**
- 本课知识图谱回顾
- 进阶方向：RTOS、更复杂的总线（CAN / USB）、更系统的控制算法
- AI 协作的长期习惯：上下文库、提示词库、验证闭环的复用
